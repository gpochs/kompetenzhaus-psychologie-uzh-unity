# Kompetenzhaus WebGL shell

The custom template is a semantic DOM interface over the actual Unity game. Unity owns learning progress, curriculum projection, quiz shuffling/correctness, architecture validation and persistence. `shell.js` sends commands and renders returned snapshots. It never awards progress or calculates an alternative competency score.

## Build integration

Copy `index.html`, `shell.css`, `shell.js`, `bridge-contract.mjs`, `framework-view.mjs` and `shell-locale.mjs` together into the Unity custom WebGL template. Unity substitutes the standard loader/data/framework/code filename and product placeholders in `index.html`.

The [published game](https://gpochs.github.io/kompetenzhaus-psychologie-uzh-unity/) is served from the **root of `gh-pages`**, containing the reviewed build output and `.nojekyll`. It is not the `docs/` directory on `main`. The [release record](../docs/RELEASE.md) identifies the commit and actual public browser checks. After any template change, compare the built HTML and shell files with the current template; a valid Unity loader or a passing static file inspection alone does not establish that the latest controls were copied.

The deployed directory also needs:

- `content/kompetenzhaus-content.json` (canonical public source export)
- `content/module-learning-design.json` (current canonical module proposals)
- `companion/published.json` (verified publication metadata)
- `companion/context-catalog.json` (public safe context catalogue)
- `TemplateData/cover.png` (optional generated cover; used only in the labelled welcome artwork)

Override resource paths through `window.KOMPETENZHAUS_CONFIG` before the module loads if deployment uses another layout. Optional keys: `contentUrl`, `moduleDesignUrl`, `coverUrl`, `companionUrl`, `companionEmbedUrl`, `companionPublicationUrl`, `companionCatalogUrl`.

The root Unity scene must contain the `KompetenzhausBridge` GameObject and its `ReceiveCommand` method. The embedded development `PrototypeHud` should be disabled in the final scene so it does not duplicate this DOM UI.

Do not deploy `shell-preview.html`, `preview-fixture.mjs`, `preview-framework.mjs`, `qa/`, or the tests. `?shell-preview=1` intentionally suppresses Unity loading and visibly labels the UI as a preview. The standalone preview adds explicit development controls and never represents itself as a functioning 3D game. The `qa/framework-v2-*.json` files are actual C# JsonUtility projection exports from explicitly synthetic game states. They contain proposed opportunities and no assessment records. The older legacy QA files are retained for regression history and are not consumed by the current preview.

## Contract

`window.KompetenzhausBridge.receive(json)` consumes schema 1 host snapshots. `window.KompetenzhausBridge.send(command,payload)` sends a whitelisted `{command,payload}` JSON envelope to `unityInstance.SendMessage('KompetenzhausBridge','ReceiveCommand', ...)`. `window.KompetenzhausShell.attach(instance)` establishes the transport and requests the initial snapshot.

Questions use the host's shuffled display order. Selection is local until **Antwort prüfen**. Feedback remains until **Weiter**, including the final question. **Complete** uses `closeQuiz`, never `continue`. The complete host explanation is displayed, and the feedback section is scrolled into view. Opening a native dialog moves focus into it, traps Tab, supports Escape, and freezes Unity controls through `setUiFocus`.

Web exploration uses W A S D to move and holding the left mouse button while dragging to look around. It does not require browser pointer lock. The focused learning place's localized host `interactionHint` appears in a separate readable status field only when a module or quest is focused. The shell does not start an additional quiz or infer a target from that text. Escape still closes native dialogs. This control change addressed fatal pointer-lock errors observed in Edge and the in-app browser; drag-to-look was then verified in the rebuilt player and the public release.

Beginner controls follow the current DE/EN shell labels:

- **Bauen / Build:** click the 3D canvas to give it keyboard focus, then use **W A S D** or the **arrow keys** to pan the bird view. Visible **+ / −** controls are labelled **Ansicht vergrössern / Ansicht verkleinern** (**Zoom in / Zoom out**) and send `zoomIn` / `zoomOut` to Unity. Click a learning place to open its task.
- **Erkunden / Explore:** use **W A S D** or the **arrow keys** to walk. **Hold the left mouse button and drag** to look around in the Web player. Press **E** near a learning place; its localized hint identifies the focused target.
- **Panels:** open dialogs pause movement. **Esc** closes them. When the layout grid has focus, arrow keys select a tile and Space applies the drawing tool. Click the canvas again when returning to movement.

These are keyboard/mouse controls; responsive layout checks do not establish complete touch locomotion. The twenty UI/contract tests were rerun successfully after the zoom and help-text changes. Actual input, camera and learning interactions were also checked in the rebuilt player; the [public check](../art/review/public-release.json) records its precise scope.

Architecture transactions clone the returned state and submit a complete candidate for host validation. Grid bounds are −4…3, floors 0…3, 4 m per bay and 64 floor tiles per house across all floors. Decorations use local metres and follow room moves by `delta * gridSizeMetres`. Undo concerns architecture only. Built modules stay in the host inventory when a plan is replaced.

The connection editor offers doors only across a shared same-floor wall. Stairs connect different rooms at identical x/z coordinates on consecutive floors. Both endpoint cells must be clear of module footprints, furniture centres and other stair endpoints. The lower endpoint also needs access from its own room, an explicit doorway or the ground-floor automatic entrance; this mirrors `ArchitectureCirculationPlan` and does not replace host validation. Candidate filtering never deletes furniture. Removing a connection is a separate architecture transaction. Floor and roof controls send `setArchitectureView` to keep the cutaway aligned with the selected plan floor.

Settings expose master volume plus ambience, effects and footsteps gains. Mix payloads include `audioMixVersion: 1`; absent category gains default to 1, while zero remains muted. Settings changes and the master mute control preserve the other accessibility fields. The preview intentionally begins with a legacy snapshot without category gains. Selecting another house returns the preview to bird view, matching the host command.

The optional **Studium** menu contains the module catalogue, all canonical competencies and the activity-based career compass. `framework-view.mjs` renders only `snapshot.frameworkProfile`: canonical criteria, task levels I–III, proposed tasks/evidence/success criteria, and 14 Future Skills / AI perspectives. A perspective filters the same canonical criteria and matching task contexts; it adds no points. The 12 career views show activities, proposed opportunities and next modules returned by Unity. Optional digital contexts are labelled optional. Each competency can display its source-authored AI role, learner contribution, proposed assessment focus and example task through `aiIntegration`; these use the same canonical criterion IDs. Competency counts and headings are read from the host, so the V2.1 technical split does not require hardcoded UI totals. Personal competence remains unassessed. Quiz/quest practice is shown separately. Missing V2 data produces an unavailable message, never legacy levels, radar, percentages or career-fit scores. `snapshot.profile.credits` is used only for academic module-credit totals. Source-derived topic/module choices in the existing module UI remain available.

The entry guide offers a first room, an optional editable preset or a direct source quiz. Its navigation helper reads Unity eligibility and placements; it cannot award achievements. After a quiz on an empty plot, the build action opens the room editor. Room name and size are immediate; plan drawing, floors, geometry and connections are expandable. The room commit and next learning action remain visible in the builder footer. Optional `snapshot.journey` from Unity adds the current main quest with purpose, instructions and location; it does not lock free building. The profile is independently loaded through the V2 host snapshot.

An AI iframe requires explicit opening, an allowed hostname and `embedGenerationVerified === true` in publication metadata. The current value is `false`, so the released game provides the verified external Claude link and optional context copy without mounting an iframe. The v3 envelope includes only known active-mode module IDs/choices, known quiz/quest practice IDs and an allowlisted framework version. It never exports legacy competence levels, field scores or career-fit percentages. It omits names, room labels, notes and conversation text. No automatic cross-frame transfer is claimed or attempted.

The [published V2.2 companion](https://claude.ai/public/artifacts/28b92e04-206d-41b5-ad4e-2382126be043) produced actual German and English Claude responses in Tutor mode. On Pages, the embedded UI loaded but returned no answer to the test question; the same question produced a genuine response on the external Claude host. Its 39 mock-host tests and the earlier V2.1 four-mode/conversation checks are separate evidence. See [publication metadata](../companion/published.json) for the exact source hash, tested scope and remaining German status/accessibility labels.
